# Spec — declared resource limits are reported, never enforced

**Contract.** The supervisor samples each live job's CPU and resident memory on
the interval it already ticks, keeps a short recent window, and reports whether
the latest reading crosses a limit the job's declaration stated. **It never
throttles, renices, or kills a job for crossing one.** The limit fields exist in
the manifest schema from the first release, so adding enforcement later is
additive rather than a change every manifest must follow.

**Why monitoring is the feature.** The question that motivated a machine-global
supervisor was *what is wedging this machine?* — a runaway build freezing a box
while nothing had a view wide enough to name the culprit. Sampling answers that
question completely. Enforcement answers a different one, and the two share a
word only by accident.

**Rejected — kernel enforcement (cgroup v2) now.** It is the right mechanism
eventually, and the wrong one to start with: it needs delegation set up outside
this program, it is Linux-only, and it would gate the answer to the original
question behind deployment work that has nothing to do with it.

**Rejected — `nice` and rlimits as a cheap stand-in.** Coarse, and per-process
where the interesting runaway is a process *tree*. A cheap enforcement that
misses the actual case is worse than none, because it reads as covered.

**Rejected — killing on breach.** A job crossing a ceiling is overwhelmingly the
job someone is trying to diagnose. A supervisor that kills it destroys the
evidence, and does so at the exact moment attention arrives.

**Consequences that follow.**

- A **rate needs two readings.** One `/proc` sample is a total since process
  start; reporting it as load would show every job spiking on first sight. The
  first sample of a job reports no CPU rate and establishes the baseline.
- A job with nothing running contributes **no sample**, not a zero one. Zero
  reads as *idling*; absent reads as *gone*, which is what is true.
- History is a **short window** (a minute at the daemon's tick), not a series.
  A supervisor that grew into a metrics store would keep data nobody queries at
  a cost everybody pays. Anything wanting history scrapes and stores elsewhere.
- Sampling rides the **existing supervise tick** rather than owning a timer, so
  the observed elapsed time between calls is what a rate is computed against —
  no assumed period to drift from reality.

**Escape hatch.** A caller needing a reading now can force one rather than wait
out a tick. A node wanting real enforcement can declare the same limits and act
on the reported breach itself; nothing here forecloses that, which is the point
of the fields existing early.
