# Spec — boot autostart reads the node's manifest, and only the node's

**Contract.** A **node manifest** — the same schema as a workspace's, living in
the daemon's registry directory — declares what this machine runs independent of
any checkout. At startup, after re-adoption, the daemon starts every entry whose
`autostart` is `boot`. Those jobs are owned by `Scope::System` and started as
`Caller::Console`, because the daemon *is* the node.

`autostart = boot` in a **workspace** manifest is **refused at load**, naming the
entry and pointing at the two things the author probably meant.

**Why refuse rather than ignore.** Nothing discovers an arbitrary workspace at
daemon startup: the daemon knows the workspaces it happens to hold records for,
which is a function of what ran before, not of what should run. A workspace
`boot` entry would therefore either never start, or start on some machines and
not others depending on history — and both are worse than an error. A
declaration that reads as active while being inert is the most expensive of the
available failures, because it costs a debugging session to discover.

**This reverses an earlier decision**, deliberately. `ensure` previously skipped
a workspace `boot` entry in silence, which was correct only while `boot` had
nowhere right to live. Once there is a right place, pointing at it beats
ignoring it.

**It is `ensure`, not `start`.** Re-adoption runs first, so a job the previous
daemon left running has already been taken back over. Starting a second copy
alongside it is the single thing a supervisor must never do, and idempotence is
what makes a daemon restart safe rather than eventful.

**A node entry must declare an absolute `cwd`.** There is no workspace root to
fall back on. An ambient working directory for a system service is a bug that
surfaces later attached to something else, so it is refused up front — and
refused *before* anything starts, so a broken entry cannot leave half a boot
behind it.

**Gates.** The **host** gate still applies: one manifest may be shared across
machines, and that is precisely how a machine-specific job stays on its machine.
The **worktree** gate is skipped — it asks which checkout of a repo this is, and
a node-level job is in no repo.

**A failed entry does not abandon the boot.** One service that cannot spawn must
not keep every unrelated service down.

**Rejected — deriving boot workspaces from existing records.** The daemon could
re-read the manifests of workspaces it previously ran jobs for. It is coherent
and it is worse: what starts would depend on what happened to run before, so the
same manifest would behave differently on two machines and differently on one
machine over time.

**Rejected — a separate schema for node jobs.** The two differ in which manifest
was read and which scope owns the result, and nothing else. A second schema
would be a second place for the same fields to drift.

**Escape hatch.** The node manifest's location follows the registry directory,
which is already configurable, so packaging can put it under `/etc` without this
crate knowing anything about it.
