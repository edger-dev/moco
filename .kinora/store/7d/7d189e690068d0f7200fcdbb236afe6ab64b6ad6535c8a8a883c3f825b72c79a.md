# Spec — every device works through a local place; a write is done locally

**Contract.** Each device has one mandatory local place, its working copy.
Kinora and kura read and write only it. A miss reads through to the other
places; a write goes through to the places policy names. The ledger trees are
never evicted from a working copy; media is evicted by policy, oldest first.

A write is done once it is in the working copy and queued to push. Whether it
is safe is a separate question, answered by inventories and policy: kura says
"safe to wipe the card" only when each original shows in enough verified
places.

**Why.** Offline-first: every read is local, so nothing a reader does waits on
the network, and this is how kinora (plain files) and kudo (pull before start,
push at submit) already work. Splitting "done" from "safe" lets offline
writes work without ever claiming a durability it does not have.

**Rejected.** A configurable stack in which a process may read remote places
directly (every reader then handles the network failing). A write done only
once the meeting point has it (no offline writes).

**Escape hatch.** A process with no disk of its own (a phone's viewer) may use
an in-memory working copy; the rules are the same, only nothing persists.
