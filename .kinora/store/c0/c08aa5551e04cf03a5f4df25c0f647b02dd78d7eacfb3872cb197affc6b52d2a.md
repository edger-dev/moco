# Spec — mutable state is an append-only stream of write-once objects

**Contract.** Anything that would be a mutable pointer — a root's current
version, a place's inventory snapshot — is instead a **stream**: write-once
objects under one prefix, each named `<ts>-<hash>`, the latest found by
listing. Two writers appending at once leave two entries; readers see every
head and the next writer folds them (its object names both as parents). No
compare-and-swap anywhere. A stream is a convention over put-once and list,
offered as a library helper, not a trait operation.

**Why.** Forks, not locks: it is the one shape that needs no conditional
update, works offline, and behaves the same on a file system, an object store
and in git (where added files never conflict). Kinora already represents
multiple heads.

**Rejected.** Compare-and-swap on one key (a lock in disguise, a sixth
operation, provider-dependent, no offline writes). One designated writer
(stalls while it sleeps).

**Escape hatch.** A stream that grows long may be compacted by writing a
checkpoint entry that names everything before it; the old entries become
removable under the place's own policy.
