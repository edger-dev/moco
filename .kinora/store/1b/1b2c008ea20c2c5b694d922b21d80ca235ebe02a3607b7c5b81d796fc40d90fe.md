# Task — a job's exit survives its node restarting

A configuration switch that restarted its own node ended `outcome-unknown`:
the re-adopted job's exit code was lost, because no process that outlived the
daemon kept it (kudo finding: kino://ab39d35e5a302333c60baa345c55f92821806d7f4334e5cc4cc3de03f93457cc). A deploy of the node
through the node is a normal operation, and its record should say how it
ended.

- kino://0119d16e256891de4a71a14418f59c33419207f49792e58001639f8cbef567a6 (v2) — a job survives restarting the daemon that spawned it; its exit survives too

## Done-when

- Where the node has its holder, every job runs under it: a log-lens job
  through a `--logs` mode (no pty; output straight to the capture), a
  terminal one as today. The holder writes the job's exit code beside the
  capture when the job ends.
- A re-adopted job that ended reads that file: done with its real code. With
  no file it stays `outcome-unknown`, and kudo words it as the node having
  restarted under the job.
- A program that cannot start is still refused at start, not reported as an
  exit code.
- Tests first; zero warnings; reviewed.
