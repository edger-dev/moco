# Spec — commands cross the host boundary as argv, never a shell string

**Contract.** A cross-node command is carried and executed as an **argument
vector** (`["tool", "sub", "--flag"]`) and the daemon spawns the program directly.
Shell metacharacters (`;`, `&&`, command substitution, redirection, backticks) are
therefore **inert data**, not control flow. `cwd` is validated to lie within a
node-configured allowed root (no `..` escape) and the resolved cwd is echoed back.

**Chosen.** Argv-only execution. This closes the command-injection surface **at the
type level**: the rule-set decides *which* argv may run; the argv shape guarantees
it cannot *become* something else. It also keeps the audit meaningful — every
recorded argv is exactly what ran.

**Rejected.** A shell string filtered by a prefix/pattern allow-list. Pattern
matching over a shell string is bypassable (`ok-cmd; rm -rf …`), making "secure"
only best-effort.

**Escape hatch.** A command that truly needs a pipeline or redirection ships a
wrapper program as `argv[0]`; the argv boundary is never relaxed to a shell string.
