## Phase 1 — env and human_view on an ad-hoc start

`StartRequest` gains `env` and `human_view` (both optional on the wire);
`JobRequest` gains `env`, applied at spawn on both paths (direct and holder).

Status: done (21 Oct). Reviewed: env got past the rule-set (a governed node now
refuses it), an older node dropped the fields silently (the reply now says
what was applied), invalid names reached the spawn (refused at the wire).

## Phase 2 — input to a terminal job

An `input` wire call; the holder reads a FIFO beside the capture and copies it
to the pty master; without a holder, the daemon writes the master directly.

Status: done (21 Oct). Reviewed: a job not reading froze the whole registry
(input now queues to a per-job writer, never under the lock), input died with
a restart (the view is persisted), large input half-landed (capped at one
atomic write), and input was an unaudited third human write (console only,
counted in the audit; intervention spec re-versioned to name take over).
Findings filed: a racy stats test, pty fds not close-on-exec, a killed
holder's leftover files.
