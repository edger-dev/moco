# Spec — each place owns its inventory; copies of it travel to the meeting point

**Contract.** A place records what it holds in its own inventory: per hash,
its size and when it was last verified. The place updates it on every put and
every verify; only the place's own machine writes it. Snapshots and deltas of
each inventory are copied to the meeting point as write-once objects (an
append-only stream), so a device that cannot reach a place — a disk in a
drawer — still knows what it holds and how fresh that knowledge is. An
inventory is a derived projection: a place can always rebuild it by walking
and hashing itself.

**Why.** Offline places cannot be asked, so presence must be recorded to judge
backup policy ("is every starred original on three places?"). Records go
stale (a file deleted outside kura, bit rot, a dead disk), so a record carries
its last verification: an unverified copy is a weaker copy. The place is the
authority on itself — the same rule as removal running only where the place
is.

**Rejected.** Probing only (blind to offline places). One central location log
every writer appends to (facts about a disk written by whoever copied to it;
a disk read offline cannot reconcile). One file per fact (a million files for
a modest archive).

**Escape hatch.** A place too large to walk often may verify a sample per pass;
its inventory still states each hash's own last-verified time.
