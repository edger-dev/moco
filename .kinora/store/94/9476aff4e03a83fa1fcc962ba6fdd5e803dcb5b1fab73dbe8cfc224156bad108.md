# Finding — stats_round_trip_over_bytes can race a process that has not started

`tests/wire.rs::stats_round_trip_over_bytes` samples right after `start` and
asserts the latest sample's RSS is above zero. Under a parallel test run the
child may not have exec'd yet, so the first sample reads 0 and the test fails
(seen twice in about a dozen full runs on 21 Oct; never alone). Wait for a
non-zero sample (bounded) instead of sampling once.
