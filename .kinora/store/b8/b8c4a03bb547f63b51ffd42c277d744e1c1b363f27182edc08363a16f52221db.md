# Spec — adopting a foreign process is the re-adopt path, parameterized

**Contract.** `adopt(scope, spec, pid)` hands an already-running process to the
supervisor. It is **factored out of** the re-adopt path of
kino://a8f6cfd51b1c823d4f9331e01962f7c2b88976587cff32120f3ce98a803c24c7 and shares it
exactly: read the pid's recorded start-time, build a detached entry with no child
handle, insert, persist, spawn the liveness monitor. The already-running guard
applies.

Adoption is a **lifecycle spectrum, not a separate kind**:

- `restart = never` **and no command** → **observe-only**. The job is listed, its
  state comes from liveness, it settles when the pid dies, its port joins the
  reserved set, and the supervisor **never respawns it** — so it cannot fight a
  human restarting that process by hand.
- Give it a **captured command** and stop/restart begin working. Because a later
  restart would *spawn* that command, the command is **gated on adopt**
  (kino://a457400202f392b8f3cb8c1266e0e7a8b4ca92ed3cff07e1fcd54e1952442226).
  Observe-only has no command, so there is nothing to gate.

Adopted entries are marked **`external`** — a persisted flag, preserved across
re-adopt and surfaced on the wire model — distinguishing "handed over" from
"supervisor-started and detached".

Cross-process hand-over is a connector method: a peer that dialed in registers
itself with the daemon that accepted it, and **the daemon hands over itself** at
startup.

**Chosen.** Adoption as a parameterization of machinery that already exists. This is
what makes the bootstrap loop tractable: the transport cannot be a supervisor-started
job, because the management plane reaches the supervisor *through* that transport —
yet it should still appear in the job list like everything else. The goal is
**visibility**, not supervision.

**Rejected.** A parallel read-only "observed" subsystem — observe-only is just adopt
with `restart = never`, and a second subsystem would duplicate the monitor, the
registry, and the liveness machinery re-adopt already has. Also rejected: making the
transport a supervisor-started boot job, which is circular and would force it into
the packaged toolset.

**Escape hatch.** A process the supervisor should watch but never touch is adopted
observe-only; there is no way for that entry to acquire a respawn.
