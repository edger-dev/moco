# Spec — the job connector is byte dispatch owned by the engine

**Contract.** The job substrate exposes its remote surface as a **byte-dispatch
entry point** owned by moco:

```
dispatch(registry, method: &str, request: &[u8]) -> Result<Vec<u8>, …>
```

The engine defines the request/reply types and **owns their encoding**; both
sides of the wire are moco's, and no other component decodes them. The entry
point takes and returns bytes, names no transport type, and links no transport
crate.

**The adapter that registers this with a daemon lives outside moco.** Making the
dispatch surface reachable is a *composition* concern: something assembles a
daemon out of a transport and one or more engines. That assembly may depend on
both; moco depends on neither it nor the daemon.

**Chosen.** Byte dispatch, so "the engine links no transport" stays literally
true — the property that let the prototype's supervisor be re-hosted from a
standalone daemon onto an existing one with its core untouched, and the one the
design brief says to keep above all others. Owning the codec on both sides is
also what keeps a component-version mismatch harmless: only bytes cross a
boundary, never a `Facet`-derived type, so the engine and the transport may sit
on different versions of the same serialization framework — which today they do.

**Rejected.** Implementing the daemon's `Connector` trait directly in moco. The
trait lives in the node daemon crate, not in the published protocol, so this
would bind moco to node-local internals — which
kino://66b68fd402b1ff45e6782ec73f4211b845c29d498058239e66b7b946b60f490c forbids
in as many words. Also rejected: having the node daemon depend on moco so it can
register a job connector itself; that is the transport-depends-on-engine edge,
and it would mean the daemon must be rebuilt to gain a capability it does not
care about.

**Escape hatch.** If the daemon's connector trait is ever published as part of
the protocol rather than living in the daemon crate, moco may implement it
directly — the trait would then be "the hub's published protocol", which this
substrate is explicitly allowed to bind. The dispatch entry point remains
underneath either way, so nothing else changes.
