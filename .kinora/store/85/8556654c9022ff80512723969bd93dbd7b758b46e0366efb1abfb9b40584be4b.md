# Spec — one substrate; lifetime is an axis, not a second kind

**Contract.** A supervised long-running process is **a job**, not a parallel kind of
thing. Every job declares a **lifetime class**:

- **`oneshot`** — expected to end, **bounded by an execution deadline**, restart
  policy always `never`.
- **`service`** — expected to keep running, **has no deadline**, and carries a
  restart policy (kino://4a14c5bdff087820e8df4b5b87654e37b8fc96c6fc033c137674c41c45b2db7d).

Terminal states record only what the OS reported — `exited(code)` · `signaled(sig)`
· `killed(requested)` · `timed-out` · `outcome-unknown` — and are **interpreted** by
lifetime class: for a `oneshot`, `exited(0)` is success; for a `service`, **any
un-requested exit is a failure regardless of code** (a dev server that exits 0 is
still down). That single rule is what drives `restart = on-failure`.

Three further axes are orthogonal to lifetime and meaningful for every job:
**declaration** (manifest entry · ad-hoc · adopted), **lenses**
(kino://87de8deda0d374227bc1db4dc01f10b9ddae108e02857ba3190f1791d1dfb43f), and
**scope** (kino://0d85bf8a00d18597ab8446e3ff9a95c7e1a25e7e0866cf33f03f4509c2f57c2f).
**One registry, one gate, one audit, one tail mechanism** serve every combination.

**Chosen.** A single substrate with lifetime as a declared axis. The five job
properties of
kino://55d28d80a3fd69d2a967aa731742a09c21bddfcac77514d4a75d275207847831 already hold
for a supervised process — id, live output, control handle, terminal record,
detachment — so a "managed process" is exactly a job carrying a restart policy, a
declaration, and lenses. Separating the raw terminal fact from its class-dependent
interpretation keeps one state set instead of a union.

**Rejected.** Two parallel substrates — a job registry beside a process registry —
which the source brief assumes because the prototype grew them months apart. That
duplicates persistence, tail, audit, and, decisively, gives the trust gate **two**
wiring points; the second is where a hole appears, as the brief's own "restart does
not re-run the admission gates" demonstrates. Also rejected: a merged union state
set carrying `crashed` as a distinct state, when `crashed` is simply an un-requested
exit read under `service`.

**Escape hatch.** Lifetime is a declared field, never inferred from observed
behavior. A one-shot that legitimately needs to outlive a deadline is declared a
`service`; the class is chosen by the author, not guessed by the supervisor.
