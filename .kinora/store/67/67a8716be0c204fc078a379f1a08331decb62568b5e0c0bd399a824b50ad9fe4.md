## Shape decisions (night shift, 24 Oct)

- **Sync trait.** kinora is sync and dependency-light; the trait uses
  `std::io::Read` streams. Async places (S3, hub) offer a blocking face that
  runs its own runtime, as `kinora-remote` already does.
- **A key names its content.** A key is a relative path of plain segments
  (`[A-Za-z0-9._-]`, no leading dot, no `..`); its last segment is
  `[<prefix>-]<hash>[.<ext>]`. Put-once refuses a key that does not name the
  declared hash. So verify and an inventory rebuild need no stored records,
  two writers of one key always write the same bytes, and kinora's layout
  (`store/<ab>/<hash>.<ext>`, `staged/<ab>/<hash>.jsonl`) fits unchanged.
  Dot-names are the place's own (temporaries, its inventory), never listed.
- **Hash** keeps kinora's public API (`of_content`, `as_hex`, `shorthash`,
  `shard`, `FromStr`, `Display`), plus a streaming hasher, so kinora can
  re-export it.

## Phases

1. **moco-place core.** `Hash`, `Key`, `Capabilities`, `Place` (put_once,
   get with range, exists, list one level, verify, inventory), `FsPlace`,
   `MemPlace`.
2. **Streams.** Append `<prefix>/<ts>-<hash>`; list entries in order; heads
   given a parents reader.
3. **Inventories.** A place-owned inventory updated on put and verify
   (`FsPlace` keeps it under its own dot-dir); snapshots published to a
   meeting point as a stream; rebuild by a walk.
4. **Working copy.** A local place plus named remotes: read-through on a
   miss (checked on arrival), write-through queue persisted locally, push by
   policy, eviction local only and never of ledger trees.
5. **moco-place-s3.** Port kinora-remote's object-store code: `s3://`,
   `file://`, `memory://`; conditional create; ranged get; blocking face.
6. **kinora on places.** Content store and staged events through a place;
   root versions as a stream, migration of `roots/<name>`; commit no longer
   main-only. Re-version kinora's mirror and extraction specs.
7. **Hub store connector** (kudo): a node serves its places, put-once and
   reads only; a hub-client place.
