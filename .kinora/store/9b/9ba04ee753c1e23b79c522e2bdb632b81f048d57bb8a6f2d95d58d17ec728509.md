# Task — a node's own recipes, listed and started by name from any host

A second host replaced its earlier process manager with kudo, whose main use
was named recipes on that host; today an agent must know each exact argv,
written down outside kudo (kudo finding:
kino://ab39d35e5a302333c60baa345c55f92821806d7f4334e5cc4cc3de03f93457cc). The node's own manifest already
declares jobs; its manual entries become recipes any caller can list and start
by name, through the gate.

## Done-when

- A `recipes` wire call lists the node manifest's manual entries this node may
  run: name, argv, cwd, lifetime and what each is for (a new optional `about`).
- A named start with `node_recipe` starts that entry from the node's manifest,
  owned by the caller (so the caller can kill it), through the gate exactly as
  an ad-hoc start of the same argv; an entry without a cwd, for another host,
  or not manual is refused with a reason naming it.
- A restart of a recipe job reads the node's manifest again, not the caller's.
- kudo's shim offers a `recipes` tool and `job_start` with `node_recipe`;
  the process-manager docs say how.
- Tests first; zero warnings; reviewed.
