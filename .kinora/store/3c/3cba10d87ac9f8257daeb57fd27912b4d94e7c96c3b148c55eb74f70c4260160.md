# Plan — a job's exit survives its node restarting

**Task:** kino://1b2c008ea20c2c5b694d922b21d80ca235ebe02a3607b7c5b81d796fc40d90fe

Two phases, each tests → implementation → fresh review → fixes.

1. **moco.** `HolderPaths.exit` (`<capture>.exit`), written atomically
   (temp file, rename) with the code the holder exits with — the job's own,
   or 128 + the signal that ended it. `--logs`: the holder spawns the job
   with its own stdio (the capture, stdin null) in its own process group,
   publishes the job's pid, waits, writes the exit, exits with the code.
   `spawn_child` sends log jobs through the holder when one is configured,
   after checking the program resolves on the effective PATH (a missing one
   is the same `Spawn` error as today). Re-adoption and the adopted-job
   settle read the exit file before settling `OutcomeUnknown`; a killed job
   stays `Killed`.
2. **kudo.** An `outcome-unknown` job the node did not adopt from outside
   reads "outcome unknown: the node restarted under this job" in the shim's
   listing and wait replies and in the console.

Not in this slice: a node without the holder keeps today's behaviour (no
exit file; the wording still names the restart).

Phase 1 built and reviewed (23 Oct; e13c2bc tests, 0a3d492 implementation,
review fixes): log jobs run under the holder (`--logs`), which writes the
exit beside the capture; re-adoption and the adopted settle read it. The
review caught two regressions, both fixed and tested: the holder died of a
group stop at once, so a job ignoring SIGTERM was recorded stopped and never
force-killed — the holder now blocks the stop signals once the job is
spawned (a child inherits the mask, and resetting it in the child would take
unsafe `pre_exec`; a stop in that instant takes the holder early, the job
still gets the signal); and a deadline killed only the holder — it now
signals the whole group. A job's own PATH is searched at the start. Found on
the way: a held terminal job never ended (the holder kept its slave
descriptors open); fixed. A job ended by a signal under the holder reads 128
+ the signal, not -1. A node whose holder predates `--logs` fails every log
job: deploy the holder and the daemon from one moco.
