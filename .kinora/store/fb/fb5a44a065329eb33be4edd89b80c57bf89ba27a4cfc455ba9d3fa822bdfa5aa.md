# Plan — v1: the local governed job (single-node substrate)

**Task:** kino://a666bbacd1364ab96454adbf6e922e917fef86303eb34a874c165d4ceaca573f

The smallest end-to-end slice that proves the thesis (*the job is the unit, not
the RPC*) **and** the non-negotiable trust core of the first job type (*argv, not
shell* + a *fail-closed* node-owned rule-set + *audit*). It runs commands as
governed jobs on **one node, in-process** — no hub, no console, no human approval
UI. Built as a new cell `cells/moco-job` with a concrete typed Rust API plus
`CellSpec`/`FuncSpec` metadata (the moco-tty pattern), so v1 does **not** block on
moco-core growing a generic `Func`-invocation model.

Two deliberate v1 boundary calls, both re-openable later:

- **Local-only.** The job surface is kept transport-agnostic; the hub lane
  (kino://66b68fd402b1ff45e6782ec73f4211b845c29d498058239e66b7b946b60f490c,
  transport half) drops in as a later slice. The hub is still mid-build.
- **No human loop yet.** Approval is modeled as a job *state* with a programmatic
  decision API and a fail-closed default; the console projection and four-verdict
  UI are deferred.

TDD throughout: each phase writes failing tests from the cited spec first, then the
minimum to pass; whole suite green + zero warnings (the rung-1 lint rules and
`tests/architecture.rs` apply to the new crate too).

## Phase 1 — the job substrate: a local job is the unit

Prove kino://55d28d80a3fd69d2a967aa731742a09c21bddfcac77514d4a75d275207847831
and the registry half of
kino://73c1dda6dcacd49a56619c90a75aa7658996b2fde21547cd0fb1b9b8b19bb2f1.

- Create `cells/moco-job` (lib), add to workspace `members`; `[lints] workspace =
  true`; drop `tests/architecture.rs`.
- `JobRegistry` + a `Job` with the five properties: **id** (stable across a
  disconnect), **live output** (file-backed stdout/stderr capture → the tail
  source; stdin from `/dev/null`), **control handle** (kill), **terminal record**
  (retained after exit), and the seam for **detachment** (file-backed already; the
  cross-restart half is Phase-boundary/out-of-scope, below).
- Surface: `start(argv, cwd) -> JobId` (spawn the program **directly** — never
  `sh -c`; kino://0bc10c180c40eeeeb4b6f358577237b7899f047d42282661307031f996022590
  is structural, in from line one), `tail(id, offset) -> (bytes, next_offset,
  status)`, `wait(id) -> Outcome` (resumable by id), `kill(id)`, and `run` as
  `start`+`wait` sugar. States: `running → done | killed | timed-out` (an execution
  deadline bounds every run).
- `CellSpec` + a `FuncSpec` per operation.

*Tests:* `echo hello` → tail yields the bytes, `wait` returns exit 0; a `sleep`
job is `kill`-ed and lands `killed`; a run past its deadline lands `timed-out`;
`run` sugar round-trips. *Status:* **done** — `cells/moco-job` implements the
substrate (start/tail/wait/kill/run, argv-only, file-backed stdio); 9 substrate
tests + the arch test green, workspace clippy clean. Commits: `0bd1c2c` (tests),
`711ba2c` (impl), `d8d2f06` (review fixes — capture-file collision, kill intent,

## Phase 2 — the governance gate: argv rules, fail-closed, preflight

Prove kino://eec764ea23113b4e48bfb2765ca0f1aa539f364dc7c94b04e3d4fd26be79fa1d,
the state machine of
kino://373c7f8658e2f2425380f456ceaaf399eb6bb9babc38e610bbb6e6bc93c127a7, and the
preflight of
kino://b87a05c17453bc5c8479dedbe70e6823054f32c18b251615ecdc5abcba234fdb.

- A **node-owned rule-set** loaded from a **committed seed** (a Styx/facet config
  of allow/deny entries keyed by **exact argv**;
  kino://e1cb4151a2b6305296239a5afd3bbff7282b20abe377bad6531ee420be77c09b — the
  *matching* half). No agent-writable rule method exists.
- `start` evaluates the gate **before** spawn: allow → run; deny → job enters
  `denied` without spawning; no match → `pending-approval` (id returned, nothing
  spawned). **Deny beats allow.**
- **Fail-closed:** a `pending` job with no decision inside a timeout ⇒ `denied`
  ("no approver"). A programmatic `decide(id, verdict)` transitions
  `pending → running | denied` (it *stands in* for the human/console). Carry the
  **edited-argv** field on approve so the corrected-argv data path exists even
  though the UI is deferred.
- `preflight(argv, cwd) -> Disposition` — read-only, queues/runs nothing: the
  disposition a real run would get, `argv[0]` resolution on the daemon PATH (+ its
  absolute path), the effective PATH, and the **confined resolved cwd** (validated
  within a node-configured allowed root; `..`-escape is an error).

*Tests:* a seeded-allow argv runs; a seeded-deny never spawns; an unmatched argv →
`pending` → timeout → `denied`; a `decide(allow-once)` runs a pending job; a cwd
escaping the allowed root is rejected; `preflight` reports each disposition and a
missing `argv[0]`. *Status:* not started.

## Phase 3 — audit + self-describing outcomes

Prove kino://8aff220f90d785d34d4001e2e80a0b06cd3723e17215c67352ef70c1673ca61f and
the outcome half of
kino://b87a05c17453bc5c8479dedbe70e6823054f32c18b251615ecdc5abcba234fdb.

- **Every attempt — denials and timeouts included — is appended to a durable,
  append-only audit** (a local append-only log for v1; the encrypted never-delete
  backup pipeline is a system concern deferred).
- **Self-describing outcome:** the terminal record echoes the **symlink-resolved
  cwd** it ran in and the **verdict** it ran under (auto-allow / allow-once /
  seed-allow); the verdict returned to the caller is the *same* value written to
  the audit — one source of truth.
- **Legible spawn failure:** program-not-found names the binary **and** the PATH
  searched.

*Tests:* a denied attempt appears in the audit with its verdict; a completed
outcome carries the resolved cwd + verdict, byte-equal to the audit row; a
missing-binary error names the searched PATH. *Status:* not started.
