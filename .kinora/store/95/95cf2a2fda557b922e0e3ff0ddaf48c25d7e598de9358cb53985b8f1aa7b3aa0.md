# Spec — places are reached through the meeting point and through hub; removal never travels

**Contract.** An object store (S3, R2, MinIO) is the always-on meeting point:
what must be reachable with every machine asleep lives there. Each node also
serves its own local places (a NAS directory, a USB disk, its own disk)
through a store connector on hub, speaking the `Place` trait; a place on
another machine is one more backend whose transport is hub.

Over the wire a place accepts **put-once and reads only**. Removal — garbage
collection, eviction, deleting a place's copy — runs only on the machine the
place belongs to, under that machine's own policy.

**Why.** The meeting point keeps the ledger and the cloud tier available with
the laptop asleep; the connector reaches places no object store holds (a disk
on the laptop, read from the phone while the laptop is up) without running an
S3 server on every box. Additive-only remote calls mean a confused or
compromised caller can add bytes but never destroy any — the same posture as
kudo's verdicts accepted only from the console and node rules read only from
Nix.

**Rejected.** Object stores only (local disks invisible beyond their own
machine; a NAS must run an S3 server). Served only (everything dark when its
node sleeps; the meeting point demoted to a place some node serves). Removal
over the wire, even owner-gated (one bad call away from losing originals).

**Escape hatch.** A place's owner may run removal remotely by logging into
that machine — a session there, not a wire call.
