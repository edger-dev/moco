# Spec — reads are node-global; writes are scoped to the caller's workspace

**Contract.** Access is asymmetric by operation class.

- **Reads are node-global.** List, tail, screen, stats, search default to every job
  on the node, across every workspace — so *any* session can answer "what is wedging
  this machine", the question that motivates a machine-global supervisor at all.
- **Writes are scoped to the caller's own workspace**
  (kino://0d85bf8a00d18597ab8446e3ff9a95c7e1a25e7e0866cf33f03f4509c2f57c2f). Start,
  stop and restart resolve a bare name against the caller's workspace; a **foreign
  fully-qualified id is refused with a clear error, never silently retargeted**.
- **The human console is the deliberate carve-out** — the one place for global human
  action, such as hand-killing a foreign job.

**Terminal entries linger; clearing them is explicit.** A job that exits stays in the
registry in its terminal state so its fate is visible.

- **Clear removes only terminal entries** and returns the count. It never signals
  anything and never removes a live entry — stop it first.
- Scope follows the same split: the agent clears **its own workspace**; the console
  clears **globally**.

**Chosen.** Read-all, write-own. It preserves the global observability the
supervisor exists to provide while keeping destructive authority local to the
workspace that owns the job.

**Rejected.** Cross-workspace writes — convenient, and they let one session kill
another checkout's dev server by accident. Also rejected: hard isolation, which
would lose the global read that motivated the design. Also rejected: auto-pruning
terminal entries — a crashed job must linger so you can see *that* it died and read
its last output. Also rejected: letting clear kill running jobs; tombstone cleanup
and kill-all are different verbs and conflating them is dangerous.

**Escape hatch.** A human at the console may act globally; an agent that needs a
foreign job stopped asks the session that owns it, or the human.
