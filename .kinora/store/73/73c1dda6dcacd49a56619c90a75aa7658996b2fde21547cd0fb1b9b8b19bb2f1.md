# Spec — a governed cross-node command is a job, not a special RPC

**Contract.** A command an agent runs on a *different* node is an ordinary job on
the process registry — reusing the registry, scrollback ring, tail/status,
detachment + re-adoption, and console — plus exactly two additions a plain process
lacks: a **governance gate** (the node-owned rule-set) evaluated *before* spawn,
and an **audit record** written when it ends.

**Chosen.** One substrate. A command *is* a process with a rule-set in front of it,
sharing one tail/status/kill surface and one console. The surface is
`start` / `tail` / `wait` / `kill`, with `run` as blocking sugar.

**Rejected.** (a) Modeling the command as a raw "run a shell string detached"
process — unvalidated, fire-and-forget, no return value, no approval. (b) A
command-only output runner separate from the process registry — it duplicates the
whole substrate.

**Escape hatch.** A command that genuinely needs pipelines/redirection declares a
wrapper program as `argv[0]` rather than reaching for a shell string.
