# Spec — the job substrate is realized as a moco cell layer over the hub

**Contract.** The job substrate is built in **moco**, not in the hub. It is
realized as moco **cell(s)** whose **Funcs** are the job surface, carrying
`FuncSpec` metadata like any other moco function:

- **one-shot core** — `start` / `tail` / `wait` / `kill` / `preflight` / `run`
  (with `run` as `start` + `wait` sugar);
- **supervision** — `list` / `stop` / `restart` / `ensure` / `adopt` / `clear`;
- **observation** — `screen` (the faithful VT screen of a terminal-lens job) /
  `snapshot` / `stats`.

One parameterized surface serves both lifetime classes
(kino://8556654c9022ff80512723969bd93dbd7b758b46e0366efb1abfb9b40584be4b); there is
no second, parallel surface for long-running jobs.

**The engine is transport- and consumer-agnostic.** It links **no** transport,
**no** MCP SDK and **no** UI framework. It exposes a library API; every consumer —
the hub connector, an agent-facing shim, a console — is a **thin adapter over that
API**, and adding a consumer requires no change to the engine.

The substrate **rides on the hub** for transport and node routing only: the hub
relays connectors and knows nothing of jobs, rule-sets, approvals, or audit. The hub
boundary stays swappable; moco binds to the hub's published protocol, never to
node-local internals.

**Chosen.** Put the job substrate in the moco layer as composable cells over the
moco `Cell`/`Func` model, with the `Env` trait supplying the runtime context a cell
needs (registry handle, node identity, rule-set/audit backends). This keeps the
substrate a first-class moco capability others compose with, and keeps the hub thin
(pure relay). Consumer-agnosticism is what lets the engine be re-hosted — the
prototype's supervisor survived being moved from a standalone daemon onto an
existing daemon **with its core untouched**, and that portability is the deliverable.

**Rejected.** Implementing the job substrate inside the hub (the hub is transport +
topology + deploy; teaching it jobs collapses the boundary the hub brief protects);
building it as a bespoke service outside moco's cell/func model (loses
composability and the typed-spec surface moco exists to provide); and **baking the
MCP or HTTP protocol into the engine**, which couples the reusable heart to one
caller. Also rejected: standing up a second per-node daemon to host supervision —
host the capability on the daemon that already exists.

**Escape hatch.** A capability the moco↔hub protocol cannot yet express rides the
hub's opaque routed-call payload until it earns a first-class method — the hub gains
no job-specific surface.
