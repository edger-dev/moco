# Spec — a job is owned by its workspace or the node, never by a session

**Contract.** Every job carries a **scope**, and the scope is its owner:

- **`Workspace`** — identified by the **canonical git worktree root** (falling back
  to canonical cwd outside a repo). Names are unique *within* a workspace; the
  fully-qualified id is `workspace:name`, so each worktree may define its own
  `check`. Declared in a manifest at the workspace root.
- **`System`** — declared in a **node-level** manifest, **cwd-independent** (it runs
  a binary; cwd defaults to `$HOME`), unique by name, tied to no repo. This is where
  node daemons themselves live.

Sessions are ephemeral clients that **attach**. Ending, restarting, or
disconnecting a client never stops that workspace's jobs — the supervisor outlives
every client.

**Chosen.** Scope-as-owner with two scopes. Workspace scope makes ownership survive
the thing most likely to churn (the session), and makes the *worktree* — not the
repo, not the machine — the unit two concurrent checkouts can each hold. System
scope exists because a node daemon must not be keyed to a checkout that may not
exist, and a prebuilt binary must be runnable as a daemon with no working tree at
all.

**Rejected.** Per-session ownership — a session restart would orphan or kill a dev
server, and two sessions in one checkout would see divergent job sets; this is the
property the whole supervisor exists to provide. Also rejected: keying system
daemons to a synthetic repo workspace, which couples infrastructure to an arbitrary
checkout.

**Escape hatch.** A job that belongs to no repo is `System`-scoped; there is no
third scope and no unowned job.
