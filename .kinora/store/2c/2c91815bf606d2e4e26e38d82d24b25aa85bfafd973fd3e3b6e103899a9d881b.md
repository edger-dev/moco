# Spec — committed recipes carry env/params; the requester never supplies environment

**Contract.** A committed recipe expresses its command as argv, optionally with
validated bound parameters, and may carry: an **`env` overlay** (plaintext KV
layered onto the command environment, precedence daemon env → ssh-agent env →
recipe env, recipe winning ties), **`approval = auto | human`**,
**`requires_ssh_agent`**, and a safe variadic `{args...}` rest token for read-only
recipes. **Only a committed recipe carries env; the requester never supplies
environment.**

**Chosen.** Environment needs are declared in *reviewed VCS*, not smuggled through
a shell string or passed by the requester. For `git+ssh`, the daemon re-reads
`~/.ssh/environment` on **every** run to layer `SSH_AUTH_SOCK` / `SSH_AGENT_PID`
(the socket path is random per agent start, so a stale value is worse than none);
`requires_ssh_agent = true` fails loudly and actionably when no socket is present.

**Rejected.** The requester supplying environment (reopens the trust boundary); and
for ssh-agent: a static `Environment=` in the unit (random socket name), an
`EnvironmentFile=` (read once, stale after agent restart), or a provisioned deploy
key (the user already runs an authorized agent).

**Escape hatch.** A recipe needing a specific `PATH` or var declares it in the
committed `env` overlay; the trust boundary stays "which argv may run", never the
environment.
