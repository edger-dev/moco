# Spec — the node is the port authority; the registry is the reserved set

**Contract.** Because the node owns the full job set, it allocates dev ports. One
**port range per node** (env-overridable) — a node range, not a per-repo range.

- **The reserved set is derived from the shared on-disk registry**
  (kino://a8f6cfd51b1c823d4f9331e01962f7c2b88976587cff32120f3ce98a803c24c7), never
  from a per-daemon in-memory set. At allocation time, scan the registry's **live**
  entries for ports in use — each allocated port plus each declared fixed port.
- **`auto` allocation is sticky, then lowest-free.** If this exact `(scope, name)`
  previously held an auto port and that port is in range and free — absent from the
  reserved set **and** passing a live `bind()` probe — reuse it. Otherwise take the
  lowest free port passing both checks. The live probe is what respects ports held
  by processes the supervisor knows nothing about.
- **A node-level allocation lock** serializes scan → pick → persist across all
  daemons and all entries, so two concurrent starts cannot pick the same free port.
  It is a distinct lock from the per-entry start/stop lock.
- **Fixed ports are reserved as-is** and excluded from the auto pool.
- **Reclaim is implicit; there is no cooldown.** A port is in use only while its
  entry is live; a terminal entry stops reserving it immediately.
- **Allocation happens after admission**, so a job that is denied or refused by a
  gate never consumes a port.
- **The assigned port is persisted on the registry entry**, threaded into the live
  handle on re-adopt, and **visible everywhere** — snapshot, wire model, console row
  (sortable), and the agent's list output.
- **Delivery is environment injection**: the port reaches the process as
  `MOCO_PORT`, overridable per job via `port_env`.

**Chosen.** Centralized allocation derived from durable shared state. Under multiple
daemons the registry is the *only* correct source of truth for what is taken. The
payoff that was not anticipated is **visibility**, not collision-avoidance: "which
of my five servers is this?" stops being a question once the port is a first-class
field.

**Rejected.** A per-daemon in-memory reserved set — invisible to a peer daemon
sharing the registry, so two daemons hand out the same port. Also rejected: holding
a stopped job's port out of the pool, which starves the range and reintroduces the
cooldown this design removes — **stickiness, not reservation, is what keeps a port
stable across a gap**. Also rejected: a bare `PORT` env name, too likely to collide
with something the process or its tooling already sets; one prefix namespaces
everything the supervisor injects. Also rejected: leaving the port implicit in the
child's environment, which defeats the point of centralizing allocation.

**Escape hatch.** A job declaring a fixed integer port bypasses allocation entirely;
its port is reserved as declared and it competes with nothing.
