# Spec — the hosting daemon may vouch for a start it built itself

**Contract.** Besides the gated `start`, a governed registry offers
`start_vouched`: a start whose argv, environment and working directory the
**hosting daemon composed itself**, from values it checked. It skips the rule
gate and the environment refusal, is still confined to the allowed root, and
is audited as `Vouched`, so the record says no rule and no human admitted it —
the daemon did. It is an in-process call only: it is never on the job
connector, so no remote caller, console included, can reach it.

**Chosen.** A daemon that hosts the engine may offer typed operations of its
own (kudo's node starts a worker pane for `{context, repo, lease}`); the gate
exists to stop a caller from choosing a command line, and in a typed operation
no caller chooses one. One narrow, named entry keeps that authority visible in
the code and in the audit, instead of hiding it behind a rule the daemon would
have to write for itself.

**Rejected.** An environment allowlist on the gated start (the argv still
varies, so every start needs a human). A caller claiming the console to skip
the gate (any hub client can claim it). Writing a standing allow rule for each
composed command (the rule-set would fill with one-off entries no human chose).

**Escape hatch.** Whatever the daemon cannot compose from checked values goes
through the gate like any other start.
