# Spec — node-supplied values reach argv as `@MOCO_*` tokens, not through a shell

**Contract.** A declared argv element may contain a **node-supplied token** of the
form `@MOCO_<NAME>` (e.g. `@MOCO_PORT`). The node substitutes it **at spawn, strictly
after admission**. Two invariants make this safe:

1. **Only node-supplied names expand.** The token set is closed and node-owned; a
   requester can never choose what a token expands to.
2. **Substitution never changes the argv element count.** It is textual within one
   element, so `--port=@MOCO_PORT` is as safe as `["--port", "@MOCO_PORT"]` — with no
   shell and a node-generated value, it can neither produce a metacharacter with
   meaning nor split one element into two.

Failures are loud, at parse time:

- `@MOCO_<UNKNOWN>` → a config error naming the token and listing those available.
- Any other `@` (`@file.txt`, `user@host`) is **literal** as far as this contract
  is concerned. A particular config *format* may still require it quoted — Styx
  reads a bare `@` as an enum variant, so a manifest writes `"@MOCO_PORT"` — but
  that is the format's rule, not this one's.
- **`$` is not policed.** This clause originally made any `$`-sequence a config
  error, reasoning that no shell is involved. Implementing it proved that wrong
  twice over: a job may ship a shell as `argv[0]` — the escape hatch
  kino://0bc10c180c40eeeeb4b6f358577237b7899f047d42282661307031f996022590
  explicitly grants for a pipeline — and there `$` is the shell's business; and
  `sh -c "… $MOCO_PORT"` is then the *correct* way for that job to read its
  port, because the node injects it into the environment under exactly that
  name. A rule that refuses the intended usage is worse than no rule, so only
  the `@MOCO_` namespace — unambiguously ours — is checked.

  Kept here rather than quietly edited out: "we tried to police this and it
  produced false positives on the sanctioned pattern" is the useful part.

**The gate never sees a template.** The token is a literal constant *inside an
ordinary argv*, so the rule-set matches the declared argv **verbatim** and
kino://0bc10c180c40eeeeb4b6f358577237b7899f047d42282661307031f996022590 and
kino://e1cb4151a2b6305296239a5afd3bbff7282b20abe377bad6531ee420be77c09b require **no
change whatsoever**. Substitution happens strictly below the gate. The audit records
**both** the admitted argv (what the rule matched) and the realized argv (what
`execve` received) plus the resolved token values — the same shape as the
resolved-cwd echo already required by
kino://b87a05c17453bc5c8479dedbe70e6823054f32c18b251615ecdc5abcba234fdb.

The name is shared with the environment: the node injects env `MOCO_PORT`
(kino://8aaf8816543726ceab97e2e90dc2bca697199132c5adbdbcbc220470f72f7d18) and the argv
token is `@MOCO_PORT` — one name, two delivery mechanisms, extending to future
node-supplied values without new syntax.

**Chosen.** The sigil names the **actor**: `$` means "a shell expanded this", and
there is no shell; `@` means "the node expanded this". Choosing `@` also shrinks the
footgun surface to the `@MOCO_` prefix alone, which is why no escape sequence is
needed anywhere.

**Rejected.** Running `cmd` through `sh -c` and relying on ordinary shell expansion,
as the source brief specifies (§4, §8). It collapses
kino://0bc10c180c40eeeeb4b6f358577237b7899f047d42282661307031f996022590, and — the
decisive objection — a shell string cannot be soundly matched by an exact-argv
rule-set, so choosing it would make declared jobs **permanently ungovernable**.
Also rejected: the `$MOCO_PORT` spelling, which forces *every* unrecognized `$`
sequence to be an error (to catch a habitual `$HOME`) and therefore forces `$$`
escaping for a literal `$` in regexes and arguments. Also rejected: a general
template engine over the command — the source brief rejects it too, but on the
premise that `sh -c` already expands env vars, a justification that does not survive
removing the shell.

**Escape hatch.** A job that genuinely needs a pipeline or redirection ships a
wrapper program as `argv[0]` — the hatch already granted by
kino://0bc10c180c40eeeeb4b6f358577237b7899f047d42282661307031f996022590. The argv
boundary is never relaxed to a shell string.
