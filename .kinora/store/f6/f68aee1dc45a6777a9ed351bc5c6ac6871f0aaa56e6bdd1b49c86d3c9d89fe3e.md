# Finding — a killed holder leaves its .input and .jobpid behind

`kill` signals the holder's process group with SIGTERM; the holder has no
handler, so its cleanup (removing `.input`, `.jobpid`) never runs and the files
stay in the state directory. Harmless while input checks the job is running
first, but the state directory accumulates them. Handle SIGTERM in the holder
(forward to the job, then clean up), or let the daemon remove them when it
reaps a held job.
