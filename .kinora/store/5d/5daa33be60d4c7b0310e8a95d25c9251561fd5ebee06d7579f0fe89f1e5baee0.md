# Task — build the agent-first job substrate in moco

Realize the job substrate and its first job type (a governed cross-node command)
as **moco cell(s)** over the hub's transport. This is the umbrella tracking item;
v1 scope and a phase plan are defined in a later design round (no plan kino yet).

**Design brief:** kino://8369f19cc043b9852ce60adfeb049daf044aa114593a1758137e16a7f905ee91

**Companion task:** kino://2510f2c0c82179acb1eddd256ae315f94fa2b95e6800f343a8c84b8a2e0dd2d4
— supervision of long-running processes. A later design round established that a
supervised process **is a job**, so the two tasks build **one** substrate, not two
(kino://8556654c9022ff80512723969bd93dbd7b758b46e0366efb1abfb9b40584be4b): this task
owns the `oneshot` half and the trust core; the companion owns the `service` half.
One registry, one gate, one audit, one tail mechanism serve both. Two consequences
land here rather than there:

- the v1 plan grows a **Phase 4** that moves the registry onto disk, because
  building supervision on an in-memory registry forces monitoring, restart
  classification and port allocation to be redesigned later
  (kino://a8f6cfd51b1c823d4f9331e01962f7c2b88976587cff32120f3ce98a803c24c7);
- `argv`-only execution is reaffirmed against the process-manager brief's `sh -c`
  manifest — node-supplied values reach argv as `@MOCO_*` tokens substituted below
  the gate (kino://45fa2f39d396287efda6dc661554b12220b836db5174e0e3a3dffb490b028f2d),
  so kino://0bc10c180c40eeeeb4b6f358577237b7899f047d42282661307031f996022590 and
  kino://e1cb4151a2b6305296239a5afd3bbff7282b20abe377bad6531ee420be77c09b need no
  change.

## Done-when

- A moco cell exposes the job surface (`start`/`tail`/`wait`/`kill`/`preflight`/`run`)
  with `FuncSpec` metadata, over the hub transport.
- The first job type — a governed cross-node command — runs end-to-end: argv-only,
  node-owned fail-closed rule-set, four-verdict approval as job states, exact-argv
  "always", committed recipes with env, read-only preflight/read-rules/read-audit.
- Jobs survive a daemon restart (both kill vectors closed); "outcome-unknown" is
  reported honestly.
- Every attempt (denials included) lands in the durable audit.
- Each realizing module cites its spec via `// implements: <spec-id>@<version>`.

## Plan

**v1** — the local governed job — is **complete and resolved**:
kino://f2a290a6f2ff276985d612d0717cd5902eaf3df1cc9ead090f34ab641ede3970. It is the
smallest end-to-end slice: proves *the job is the unit* plus the trust core
(argv-not-shell + fail-closed node-owned rule-set + audit), built as
`cells/moco-job`. Phases 1–3 cover the substrate, the governance gate and the
audit; **Phase 4** moves the registry onto disk, which is where cross-restart
detachment is now realized rather than deferred. Later milestones add the hub
transport, the human console + approval UI, overlay rule mutation, and
recipes/env.

## Where this stands after v1

**Done:** the substrate, the governance gate, the audit, and a registry that is
durable node state on disk. Beyond the original v1 scope, the substrate also
gained a byte-dispatch wire surface, and is now genuinely reachable over the hub
— a job started through the mesh runs and its output reads back, proven with a
real hub, a real node and real child processes.

**Still ahead on this task:**

- **The human console projection** and the four-verdict approval UI. This is the
  interesting one: it would be the *second* consumer of the substrate, which is
  the first real test of whether the engine/face boundary holds or whether logic
  starts wanting to be shared.
- **Overlay rule mutation** — the writing of rules by "allow/deny always". v1 is
  seed-only and fail-closed; the human-gated writer is not built.
- **Recipes, the env overlay, and ssh-agent handling.**
- **Both kill vectors fully closed.** File-backed stdio and no-kill-on-drop are
  done; the `KillMode=process` unit is not written, and it is now unblocked
  because a composition root exists to package the daemon.
- **Process groups**, so a killed job's descendants die with it. Needs `libc`
  and a crate-level `unsafe` allow.
