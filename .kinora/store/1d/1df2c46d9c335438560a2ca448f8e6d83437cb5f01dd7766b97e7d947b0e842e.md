# Plan — v1: ownership, and who may write

**Task:** kino://2510f2c0c82179acb1eddd256ae315f94fa2b95e6800f343a8c84b8a2e0dd2d4

The process manager's first slice is **not** a supervision feature — it is the
question every later one depends on: *whose job is this?* Lenses, restart
policies, ports and admission gates all assume an answer, and retrofitting
ownership underneath them later would touch every one of them.

Two carved specs, realized together because each is inert without the other:
ownership without an access rule changes nothing observable, and an access rule
without ownership cannot be written.

## Phase 1 — a job belongs to a workspace, and writes respect that

Prove kino://0d85bf8a00d18597ab8446e3ff9a95c7e1a25e7e0866cf33f03f4509c2f57c2f
and kino://bb38e0d68b4090f86ae94c4ca44100c4afbfd41ffce285b61f50c599dd3e4cc2.

- A **`Scope`**: `Workspace(root)` — the canonical git worktree root — or
  `System`, which is node-level and belongs to no repo. Resolution walks up for a
  `.git` entry and takes the directory holding it, in **either** form: a linked
  worktree's `.git` is a file and a main tree's is a directory, and both are
  workspaces. Outside a repo it is the canonical cwd, so there is always an
  answer and never a null.
- Every job **carries its scope**, and the scope is persisted, so ownership
  survives a daemon restart along with everything else.
- **Reads stay node-global.** `list` reports every job on the node whatever its
  scope, because "what is wedging this machine" is the question a machine-global
  supervisor exists to answer, and scoping reads would break it.
- **Writes are scoped.** A mutation carries who is asking; a job owned by another
  workspace is **refused with an error naming both workspaces**, never silently
  retargeted or silently skipped.
- The **console is the carve-out**, and it is a named one — an explicit
  `Caller::Console` rather than an absent value, so global authority is
  something a caller states rather than something it gets by omission.
- The wire carries the caller, so the distinction survives the trip.

*Tests:* a job started from a repo subdirectory is owned by the worktree root,
not the subdirectory; a linked worktree resolves to its own root and not the main
tree's; outside a repo the cwd is the workspace; a foreign workspace cannot kill,
and the refusal names both; the console can; `list` shows jobs from every
workspace; scope survives a registry restart. *Status:* **done** — `scope.rs`
(`Scope`, `Caller`), scope on the handle, the record and the wire
(`WireCaller`), the write gate on `kill`, and `scope_of` as a global read. 9 new
tests, suite green, clippy clean. Commit: `c967553`.

Two decisions worth carrying into the later phases:

- **`.git` in either form is a workspace root.** The obvious implementation
  looks only for a `.git` *directory*, which silently attributes a linked
  worktree's jobs to whatever ancestor happens to have one — and for two
  checkouts of the same repo that is precisely the confusion ownership exists
  to prevent. (Note the distinction is still needed later, and for a different
  purpose: the admission gate's `worktree = main-only` turns on directory-vs-file.)
- **Authority is claimed, never defaulted.** `Caller::Console` and
  `WireCaller::Console` are named variants rather than an absent field, so
  nothing acquires global write authority by omitting something. The same
  reasoning put the *caller's cwd* on the wire rather than a resolved
  workspace: the caller says where it is, and the engine — which owns the rule —
  says what that means.

**Not yet reachable from the agent.** The shim still builds against an older
moco revision and sends no caller, so nothing exercises the refusal end to end.
Bumping the pin and adding the caller to the shim's requests is the next step,
and it is small.

## Later phases, in dependency order

Sketched rather than specified — each gets its own plan when it is next.

1. ~~**The manifest**~~ — **done** (`e5cb8a2`). `moco-processes.styx` at the
   workspace root, `start_named`, names on jobs, hot reload on every start, and
   the gate applied to declared jobs exactly as to ad-hoc ones. 8 tests.

   Three things worth keeping:

   - **Absent and broken stayed apart**, and a duplicate name is refused rather
     than resolved last-one-wins. Both are the same instinct: a config file must
     not quietly mean something other than what it says.
   - **The gate test is the load-bearing one.** A declared job whose argv no rule
     permits still fails closed — being written in a file the agent can edit
     earns no authority. Without that test the reconciliation is just a comment.
   - **The console cannot start by name**, because a name only means something
     relative to a workspace's manifest and the console has no workspace. The
     type says so, so it is not a runtime rule to remember.

   *Not yet:* restart re-reading and re-gating the manifest, which the trust
   spec also requires — there is no `restart` verb yet, so it lands with
   lifecycle, and it must not be forgotten there.
2. ~~**Lifecycle**~~ — **done** (`434b134`). `lifetime` × `restart` ×
   `autostart`, the terminal-state interpretation, a `restart` verb, and a
   `supervise` tick. 11 tests. **The carried-forward hole is closed**: restart
   re-reads *and* re-gates.

   Three findings:

   - **A restart mints a new job id**, so a service's durable identity is
     `workspace:name` — which is what the ownership spec's fully-qualified form
     was for, arriving here rather than in the manifest phase. `declared()`
     answers "how many times has `check` restarted?" against the declaration,
     which is the question an operator actually asks. A test written against a
     single id is the wrong test, and writing one is how this surfaced.
   - **`supervise` is caller-driven, not a thread.** The engine links no
     runtime, so the daemon owns the interval — and the tick rate becomes the
     natural rate limit on a service that crashes instantly, which is a backoff
     nobody had to design.
   - **A requested stop never restarts under any policy.** `always` means
     "always when it ends on its own", not "resist being stopped".

   *Format note:* bare `true`/`false` parse as booleans, so `/bin/true` is
   `argv ("true")`. The parser refuses the mismatch rather than coercing, so it
   is a load error naming the file, not a job that runs something unexpected.
3. **Lenses** — the human PTY view and the declared machine view.
   **Blocked, deliberately.** Who owns a `terminal`-lens job's PTY master is an
   explicitly open trilemma in
   kino://a8f6cfd51b1c823d4f9331e01962f7c2b88976587cff32120f3ce98a803c24c7,
   and the brief says to decide it deliberately rather than discover it late:
   a per-job PTY holder reintroduces the per-job component the durable registry
   just removed, an external multiplexer adds a runtime dependency, and a
   transient init scope solves durability *and* resource limits at the cost of
   VT fidelity — which is the whole point of the human lens. That is a design
   call to make with a person, not one to guess at, so it is skipped rather
   than started.
4. ~~**The port authority**~~ — **done**. `port.rs` (range, reserved set, sticky
   allocation, node lock, token substitution), `port`/`port_env` on the
   manifest, allocation at `start_named` after admission, env injection, and the
   port visible on the job. 13 tests.

   Two findings, both from building it:

   - **A string that spells a boolean did not round-trip.** Styx emits a bare
     `true` for the String `"true"`, which reads back as a bool and makes the
     *whole record* undecodable — so one `/bin/true` job made the node's state
     unreadable. Fixed separately (`b92851b`) with a regression test. Phase 4's
     durability work never round-tripped such a value, which is why it survived.
   - **The spec's `$`-ban was wrong and is revised.** It refused any
     `$`-sequence in argv on the grounds that no shell is involved; but a job may
     ship a shell as `argv[0]`, and `sh -c "… $MOCO_PORT"` is then the *correct*
     way to read the injected port. Only `@MOCO_` is policed now.

   *Format note:* Styx reads a bare `@` as an enum variant, so a manifest writes
   `argv (serve --port "@MOCO_PORT")`. That is the format's rule, not the token
   contract's.
5. **Admission gates** (worktree, host) and **adoption**.
6. **`clear`**, which is the second half of the access spec and wants tombstones
   to have accumulated first.

## Done-when (v1)

- A job's owner is a workspace resolved from a directory, persisted, and visible.
- Reads are global; writes refuse a foreign workspace with an actionable error.
- The console carve-out is explicit in the type, not implied by a default.
- Suite green, zero warnings; each realizing module cites its spec by name.
